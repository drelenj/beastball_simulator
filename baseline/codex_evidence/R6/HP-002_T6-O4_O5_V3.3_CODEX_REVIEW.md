## 3. Required final corrections

### O4-10 — Correct the historical-kick lock

Use:

`cognitive_revocation_lock = prep_started (the B0 controller exposes no cognitive abort thereafter)`

If legacy evidence cannot establish the pre-preparation revocation state, represent that separately as `legacy_not_exposed`; do not use `none`, which means the action stays cognitively revocable.

### O4-11 — Use the single canonical `EventTime` spelling

Replace O4's `EventTime{sim_tick_or_ms, substep_ordinal_or_fixed_fraction}` with O5's exact fields:

`EventTime{base_time_units, substep}`

State that `substep` is the schema-versioned quantized time coordinate and never an ordinal. At schema freeze, name the base unit and require conversion from a deterministic exact/fixed-point or otherwise parity-specified source representation; merely rounding an implementation-dependent floating value is insufficient for cross-platform identity.

### O4-12 — Actually define the route-two extension points

The status paragraph permits unresolved scenarios to be excluded behind typed, versioned extension points, but the draft does not define those types. Add at least:

- `CommitmentPolicyRef` for unresolved tackle commitment;
- `CoincidentResolutionPolicyRef` for Arrow/ball/hand ties;
- `PossessionAssignmentPolicyRef` for residual same-team ties;
- a conformance-profile field listing supported policy versions and explicitly excluded scenario classes;
- validation that an unresolved or unsupported policy produces `UNRESOLVED_*`, never a fabricated outcome.

Once these exist, tackle technique and the two physical tie cases can remain non-owner engineering work without blocking a typed-core freeze.

### O5-10 — Replace the preliminary table with a valid causal-record registry

First distinguish **causal-ledger records** from embedded/value types. `Vec2`, `Estimate`, `MatchConfig`, and other value/config records do not require their own CausalId merely because they are T6 types. Every emitted ledger record must then map to exactly one declared `(processing_stage, domain, kind)`.

The current table is invalid because:

- `config` is used as a processing stage but is absent from the stage registry;
- `root` is used as a kind but is absent from the kind registry;
- `event_batch-adjacent system record` is not a kind;
- `rules or system step` is not one stage;
- `ReactionGate` is inconsistently described as a config gate while its actual row places it in `decide` and the stimulus domain.

Minimum emitted-record coverage should include:

`ObservationFrame`, any independently emitted `AthleteView`, belief revision, `ReactionGate`, `OptionTrace`, `DecisionTrace`, `ActionIntent`, `PlanStageActivation`, `MotorCommand`, `CommandIngressResult` if emitted, `PhysicalOutcome`, emergent `PhysicalEvent`, rule evaluation, committed `RulesEvent`, committed `EventBatch`, `RandomDrawRecord`, RNG-vector hash, and any communication-delivery record emitted independently of its containing observation.

Recommended resolution for the two synthetic records:

- add declared stage `system` and kind `rng_vector_hash` for the post-step vector hash; or define another exact declared mapping;
- either keep configuration solely as referenced provenance with no causal-ledger record, or add declared stage/kind values such as `system/config_root`. Do not use placeholder enum values.

ID-19 must validate the frozen exhaustive registry.

### O5-11 — Define a non-circular committed-ID allocation key

After resolution, group records by the `local_seq` scope tuple. Within each scope, allocate `local_seq` from a schema-owned semantic order that does not contain `local_seq` and does not use provisional handle or input-container order. The registry must define that key per record family, for example declared kind rank plus causal-parent identity plus a type-specific semantic slot. Reject any residual exact duplicate that lacks an explicit multiplicity index.
